## 当前机制

search_code 支持 base/head/both（默认 head），检索冻结快照中包含未改动文件的文本。
query 为字面量；path_glob 配合空 query 用于文件发现。返回 side、规范化路径、检索范围、截断状态；空结果不是全仓不存在的证明。
read_file 每次最多100行，返回 end_line/total_lines/has_more/next_start_line；共享命中也返回正文，避免上下文折叠后只剩提示。

Reviewer 默认6个取证回合、10次工具调用；Validator 8个取证回合、12次工具调用。
子任务、父级和全局预算仍同时生效，不增发预算。格式修复额度与取证额度分别记录。
有效输出仍报告具体源码/测试缺失时，至多追加一次定向取证，仍由受限Agent工具执行；
修复JSON格式期间禁用工具，格式恢复后仅在剩余取证预算允许时恢复原工具Profile。
预算不足则保留未决限制，不回退宿主Shell、不获取新凭证、不搜索未选需求。

覆盖记录按原阶段、Slice、规范化内容去重，不为综合阶段的继承文本重复加前缀。
covered/not_applicable 声明与未决检查分开；旧“声明为已覆盖”文本记为 reported_covered 观察，不作为独立核验成功证明。
达到有限循环并不自动意味着所有维度未覆盖；仅实际未决证据结合耗尽原因记录限制。
Validator 接收带 coverage_id 的限制，核销须给出已提供/读取的当前快照代码范围；未知ID、未读引用及预算耗尽限制不能核销。
仓库关系与语义正确性仍由模型判断，不声称已实现形式化覆盖证明。
